# 食物识别与中文食物库调研

调研日期：2026-11-15。范围为厂商公开页面、官方API文档及本项目代码；未登录竞品App实测，也未核验厂商完整数据库、准确率或采购价格。

## 发现

1. 小卡健康官网宣称100万+中文食物条目，覆盖食材、家常菜、连锁餐饮、包装SKU和外卖。没有公开其去重口径、逐条来源及完整数据库，不能理解成100万种独立实测中餐菜肴。公开架构为视觉大模型理解、私有营养库匹配、AR体积/重量估算。普通食品、包装、条码、饮品、订单分开处理。来源：https://www.calmate.cc/
2. 薄荷公开提供食物营养数据及企业API。官方协议列举食物搜索、详情、分类、图片识别和饮食记录接口。这意味着可以评估授权数据服务，不必从零人工补百万条。具体覆盖、价格、数据缓存、历史记录保存和退出供应商后的可用性待验证。来源：https://ai.boohee.com/ 和 https://api.boohee.com/open-interface/v1/string/market_page?title=boohee_ai_service_20260608
3. FatSecret说明其数据由基础食物、复合食品、品牌和餐厅产品组成，综合官方数据、制造商资料及审核后的用户贡献。其搜索API文档限定可存储字段，不能默认买API等于获得整库下载许可。来源：https://platform.fatsecret.com/platform-api 和 https://platform.fatsecret.com/docs/v1/foods.search
4. 百度菜品识别提供菜名、识别置信度及每100克参考热量，标准接口面向单道菜。它不是整餐份量测量器，也不能仅据此补出所有宏量营养素。来源：https://ai.baidu.com/tech/imagerecognition/dish 和官方API PDF：https://bce-cdn.bj.bcebos.com/p3m/pdf/ai-cloud-share/online/IMAGERECOGNITION/IMAGERECOGNITION.pdf?timeStamp=1754006400081

上述为公开自述，不将宣传准确率视作独立验证。未发现能确认小卡内部模型版本、数据库采购来源、置信度策略的公开材料。

## 本项目根因

- 中文映射154条，且主要是食材，不能覆盖早餐、复合菜、奶茶和外卖。
- IdentificationPrompt禁止模型输出营养值；无尺寸参照时禁止提供照片份量。这会将普通餐图频繁变成空结果或要求填克数。
- 服务/前端验证只接受数据库食物或标签核算；AI估算不是独立数据类型。仅修改提示词会被现有校验拒绝，不能解决全链路。
- 卡片优先展示核对，而用户要先获得可理解的整餐估算及简单修正能力。

## 建议落地：AI估算主路径 + 数据校准

1. 输入分流：餐盘/复合菜、包装标签、品牌饮品、订单。UI可以统一拍照入口，后台判别场景，不要求用户先读技术分类。
2. 视觉模型返回结构化食物、做法、份量估计及依据；非视觉模型不直接承担看图。部署前用真实图片验证实际配置模型的图片输入能力、时延和费用。
3. 优先使用对应标签/准确SKU；其次可靠菜品参考；再用基础食材与明确配方计算；无匹配时允许AI给出带假设的营养估算。低可辨识图片仍可请求重拍，不为每张图强行造值。
4. 数据标记分开记录食物来源、份量来源和实际食用比例。即使密度来自数据库，只要克数来自照片，整份热量仍是估算。
5. AI估算含估计份量区间、营养区间、显示代表值、主要假设、模型/提示版本。不使用模型自报的精确百分比当校准置信度。缺失营养素保留未知；负数、无穷值、区间倒置、单位矛盾及异常量级拒绝，必要时一次修复后降级。
6. 用量改变后服务端确定计算，不能每次改“半份”都重新问模型。结果可保存为估算记录，并进入标明估算占比的每日汇总；不伪装为已称重。
7. 首页结果显示总热量与每项概览，来源放展开层。默认提供“按这份估算记录”；用户确认实际吃过后保存。常用修正为全吃/一半/四分之一、少油/普通/多油等（后者需有明确配方假设重算，不盲乘系数）。只对足以改变结果的疑点追问一次，例如奶茶容量/糖度，不弹出泛化核对清单。
8. 记录持久化保留估算来源、用户修改及计算版本，重试不重复记账；云端同步不丢失上述字段。AI估算不能直接作为审核通过的公共食物库条目。

## 推荐实施顺序

P0：新增独立AI估算结构/校验/计算路径；接通识别、结果编辑、确认记录、每日统计、云端恢复；保留现有标签与数据库路径。
P1：建立真实中文餐食评测集并做模型对比，评估薄荷授权API能增加多少覆盖。接入使用适配层，保留自有记录而非依赖供应商响应结构。
P2：运营后台增加未命中食物统计、候选菜谱/品牌资料待审、来源版本与回滚；按真实频率补库。

验收建议（目标，不是当前实测结果）：至少100组样本，分普通中餐、早餐、包装、饮品、多菜；另测模糊/空图、非食物、单位错误、品牌未知、断网和重复保存。日常清晰样本结果生成率目标>=90%，完成记录通常不超过一次补充；误差按场景与称重/标签参考独立统计，区间覆盖与拒识率同时报告。不能以“能生成数字”替代准确率，更不能只验数据库条目数量。
